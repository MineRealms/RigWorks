# 统一工作台与角色资产包

用户确认的需求，2026-11-19。此文件是持续更新的实现清单；未勾选项不能当作已经实现。Forge 1.20.1 与 NeoForge 1.21.1 必须使用相同的数据语义和工作流程。

## 责任边界

- AssimpLoader 负责导入、不可变模型资产、通用编辑文档、单一视口、Inspector/Gizmo、撤销、持久化、包容器、渲染覆盖及模块注册接口。
- RigWorks 实现角色导入预处理、骨骼和动作语义、装备、角色行为、角色应用及按玩家同步；通过引擎接口注册专属面板，不让引擎引用 RigWorks 类型。
- 普通入口导入裸 FBX，即使带骨骼，也只是普通模型；不显示角色装备按钮，不自动启用角色功能。
- RigWorks 新建/导入入口初始化必要配置并标记 `[RigWorks]`，随后仍在公共 Edit 工作台编辑；已有角色 ZIP 保留原有类型和数据。
- 编辑不回写 FBX。原始模型、贴图和声明式覆盖共同形成资产。普通模型没有实体、方块或脚本引用时，Apply 不会生成展示对象。
- “保存项目”与“导出资产包”分开。用户所说的可携带保存主要指 Export。

## 编辑与应用

- [x] RigWorks 入口预处理 FBX：继承匹配的已有角色配置，或生成骨骼/动作建议、装备默认配置和专用行为模板。
- [x] 只在明确激活的角色项目显示 RigWorks 面板，普通骨骼资产不被接管。
- [x] 单一视口与公共属性面板，删除重复的独立 Rig Editor 预览和变换控件。
- [x] 公共根变换/Gizmo 与角色配置使用一致数据，迁移旧项目时保留比例、前向校准与用户编辑。
- [x] 修复普通骨骼模型 Apply 被 RigWorks 吞掉却显示成功的问题。
- [x] 通用节点、显隐、材质颜色/PBR 与挂点覆盖接入角色实例；`head/back/spyglass` 有内建消费者，其他命名槽由扩展查询。
- [x] Save/Apply 后本地角色刷新成功；失败不宣称成功，不丢弃上一个可用实例。
- [x] 上传本人/显示他人开关继续在 RigWorks 全局选项卡中管理。

## 便携资产包

- [x] 标准 ZIP：版本化 manifest、项目配置、模型、PBR 贴图、扩展文件与逐文件校验。
- [x] 直接从编辑器导入 ZIP，恢复最后导出的全部可编辑参数；支持外部程序按相同规范创建包。
- [x] 采集实际使用的外部贴图覆盖，导出后不依赖原机器绝对路径；内嵌文件名统一为 `*N`。
- [x] 包含 RigWorks 专用 JSON/JS；本人可编辑源位于 `kubejs/rigworks/<avatar>/`。
- [x] 使用标准压缩，后台流式读写和展开预算，不把整个大型资产包常驻内存。
- [x] 路径、重复条目、损坏校验、展开大小与失败回滚验证；ZIP 导出再导入往返验证。
- [x] 导出包不是重写/烘焙 FBX，也不是 Minecraft 资源包。
- [x] 导出专用行为目录完整快照，已删除脚本不会从旧 ZIP 子树重新出现；未知扩展文件保留。

## 按玩家同步与隔离

- [x] 服务端以已验证连接的玩家 UUID 作为所有权来源；不能接受客户端伪造他人所有者。
- [x] 同样的 Rig 资产文件可共用只读网格/贴图，但 A、B 的变换、装备、动作、配置版本、运行时姿态和 Apply 必须独立。
- [x] A Apply 且启用展示时，变化才上传；服务端确认 revision/hash 后分发目录，接收者按需异步下载。
- [x] 显示他人关闭时不下载/应用其内容；重新开启后追赶服务端权威版本。
- [x] 新包验证/应用成功后替换对应玩家旧缓存；失败保留可用旧实例或明确回退。
- [x] 上传 JSON、专用行为源和配置；不上传大型 FBX/贴图。接收者必须已有匹配资产。
- [x] 他人数据只进入隔离的压缩缓存，不发布到本人的可编辑项目或脚本源目录，不开放编辑和回传他人配置。
- [x] 不新增加密。二进制压缩缓存不等于加密，也不能承诺阻止高级用户提取数据。
- [x] 不用全局 F3+T 或按资源名全体重载来更新一个玩家；局部配置变化仅替换该 UUID 的实例。
- [x] 上传最后一块时重新检查配置 revision；关闭上传同时取消服务端待提交事务。
- [x] 新解释器先暂存，待对应新 binding 成功再发布；旧 binding 的矩阵更新不能提前确认候选脚本。
- [x] 新增模型目录项不使所有角色动画和 GPU 缓存失效；目录代次与资源失效代次分离。
